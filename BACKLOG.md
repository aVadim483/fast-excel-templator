# Backlog

Known issues and cleanups that are not done yet, collected during a code audit in August 2026.
Line numbers were correct at the time of writing — check before trusting them.

Already fixed and released items are not listed here; see CHANGELOG.md.

---

## 1. Blocked on avadim/fast-excel-writer

Both are described in detail, with minimal reproductions, in `BUGS-6.16.md` of the writer
repository. Both reproduce on the plain writer, without the templator.

### 1.1 RC notation leaks into the saved file

A reference shifted off the sheet keeps its internal `R[-4]C[-1]` text instead of becoming
`#REF!`, because `FormulaConverter::normalize()` returns the unconverted match as is. The same
pattern also splits a range into halves, which can produce a hybrid `SUM(R[-4]C[-1]:A2)`.

Affects the templator directly: row templates keep their formulas in RC to re-base them on
insert. The covering test is already written and skipped:
`FormulaTransferTest::testReferenceShiftedOffTheSheetBecomesRefError` — unskip after the fix
and raise the writer constraint in `composer.json`.

### 1.2 A workbook's locale leaks into another workbook

`StyleManager` keeps a static `$instance` overwritten by every constructor, and its static
`normalizeFont()` / `numberFormatStandardized()` read `defaultFont` and `localeSettings` from
it. With two workbooks alive, the last one created wins: a `ru` workbook writes euro instead of
rouble. There is no workaround — the static holds the other workbook alive, so `unset()` does
not help.

Reaches the templator through `RowTemplate::setCellStyle()` / `setRowStyle()`, which call
`StyleManager::normalize()` statically.

## 2. Breaking changes, for 4.0

* `Excel::$instance` — assigned, never read, overwritten by every new workbook. Already marked
  `@deprecated`; remove.
* Public mutable state → getters: `SheetTemplate::$sheetWriter`, `$lastReadRowNum`,
  `$lastWrittenRowNum`, `$countInsertedRows`, `Excel::$excelWriter`, `$styleManager`. The row
  counters already have getters, so the properties duplicate the API and let callers break the
  streaming invariant.
* Four public methods named as internal: `SheetWriter::_setStyleIdx()`, `_writeToCellByIdx()`,
  `_setSheetViewsAttributes()`, `_setSheetFormatPrAttributes()`. Mark `@internal` first, hide later.
* `SheetTemplate::saveSheet()` — an empty method kept "for compatibility"; find out with what,
  then drop it.

## 3. Non-breaking, not done yet

* `Excel::download()` (`Excel.php:323`) sends `Content-Type: application/vnd.ms-excel`, which is
  the MIME type of the old `.xls`; XLSX needs
  `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`. It also never checks
  `headers_sent()` and sends no `Content-Length`.
* `RowTemplate.php:363` — `return$this->cells[...]`, missing space.
* `SheetTemplate.php:572` — `while ($rowNum = $this->readGenerator->key())` ends the loop on any
  falsy key. Row numbers start at 1, so it works by luck rather than by design.
* `StyleManager::loadElement(string $sectionName, ...)` is called with `$sectionName` still
  `null` if `styles.xml` ever holds an `<xf>` outside a known section — that would be a
  `TypeError`. Not reproduced, but the signature and the caller disagree.

## 4. Static analysis and CI

* No `declare(strict_types=1)` anywhere (0 of 10 files in `src/`).
* No phpstan/psalm in `require-dev` and none in CI — the workflow runs PHPUnit only.
  A large share of what this audit found by hand (uninitialized typed property, array key
  accessed without `isset`, `new self` instead of `new static`) is what static analysis reports
  on the first run.

## 6. Performance

Measured on a template of 20 000 rows x 4 formulas: a full pass takes ~50 s, and roughly 96 % of
that is spent writing cells inside `fast-excel-writer`, not in this package. Local optimisations
here are therefore worth single percents — the real work is in the writer.

Still, one known spot: `Reader::read()` (`Reader.php:45`) collects the attributes of **every**
element it walks into `$this->nodes`, whether the caller needs them or not.
